# FileForge privacy policy

Last updated: 2026-11-18

FileForge processes files entirely on your device, inside your browser.

- **No uploads.** Images, PDFs, text and any other files you open in FileForge never leave your computer. There is no FileForge server.
- **Network locked by your browser.** FileForge's pages carry a Content Security Policy that lets them connect only to FileForge's own files (`connect-src 'self' blob: data:`, plus `default-src 'self'` for everything else). Even if a bug or a library tried to send a file somewhere, the browser would block it. You can check it yourself: the policy is in the extension's `manifest.json` and in the web app's page, and the web app keeps working with Wi-Fi off once it has loaded.
- **No accounts, no tracking.** FileForge does not collect, store or transmit personal data, usage statistics or crash reports. It contains no analytics and no third-party scripts that load from the network.
- **Permissions.** The extension asks only for `contextMenus` (to add its right-click entries: edit, convert, read the text or read the QR code of an image; "Open PDF in FileForge"; the two screenshot entries; and "QR code for this address", which turns the address of the page or link into a QR code inside the extension without sending it anywhere), `activeTab` (so a screenshot entry can capture the tab you clicked it in, once; the picture opens in FileForge on your device and is not sent anywhere), `scripting` (when you choose a menu item on an image or a PDF, a one-off script reads that one file inside the tab you clicked, the way the page itself already loaded it, and hands it to FileForge; the menu click allows this for that tab only, through `activeTab`) and, in Chrome, `sidePanel` (to show FileForge in the browser's side panel when you choose that; it gives no access to pages). The extension asks for no access to websites. If a site does not let its own page read the file again (some image servers refuse), FileForge opens empty and asks you to save the file and drop it in. The extension never reads a page you did not use the menu on.
- **No lookups.** Tools such as QR code, JWT decoder, checksums and URL parsing compute everything in the page: no code or data is sent to any service, and a token or secret typed into the JWT tool never leaves the page.
- **Passwords and recognised text.** A password typed into Protect PDF or Unlock PDF is used in memory for that one operation; it is never saved, remembered or sent anywhere. Text recognition (OCR) runs on your device with language models that ship inside FileForge; no image and no recognised text is sent to any service. Remove background works the same way: the neural network that finds the subject ships inside FileForge (the web version loads it from its own site the first time you open that tool) and runs on your device; the photo is never sent anywhere.
- **Storage.** Nothing is written to disk except the files you choose to download. Each tool remembers the options you used last time (format, quality, page size and the like), plus the theme, interface language, recent tools, favourites and pipeline steps you picked, in the browser's local storage on your device; that is settings only, never file contents or names. The one exception is opt-in: in Sign & fill PDF you can tick "Remember my signature in this browser", and then the signature image you drew, typed or uploaded is kept in local storage so you don't have to make it again; untick the box to delete it. The web version at zhukovskyi.space/tools/fileforge/app/ keeps a copy of its own code in the browser cache so it works offline; it stores none of your files.
